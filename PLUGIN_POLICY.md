# Plugin Policy

How plugins work in MusicForge, what they may and may never do.

## 1. Distribution rules

- Core MusicForge ships **zero plugins**. Default installers, portable zips, Docker images and fnOS packages contain no plugins.
- Plugins live in separate repositories (`musicforge-plugins` for AI/online providers, `musicforge-format-plugins` for local format migration) with **independent versioning and independent licenses**.
- Plugins are **disabled by default** and must be explicitly enabled by the user.
- Plugins are loaded only from whitelisted plugin directories (e.g. `%LOCALAPPDATA%\MusicForge\plugins\`, `~/.local/share/musicforge/plugins/`, NAS `/config` volume). Arbitrary paths are refused.

## 2. Security levels

| Level | Name | Network | File access | Execution |
|:-:|:--|:-:|:--|:--|
| L0 | Pure-algorithm plugin | ✗ | ✗ | Process input data only |
| L1 | Metadata plugin | optional | read metadata only | **Return suggestions** |
| L2 | Content plugin | optional | read covers/lyrics | Return write suggestions |
| L3 | System plugin | optional | read/write | **Forbidden by default** (trusted sources only) |

**Iron rule: a plugin can never delete, move, or overwrite files — not at any level.** Plugins only return *suggestions*; every mutation is generated by the Core plan layer and executed only after explicit user confirmation, recorded in the operation Manifest, and reversible via Trash.

## 3. Permission manifest (`plugin.json`)

Every plugin must declare:

```json
{
  "id": "example-plugin",
  "api_version": ">=1,<2",
  "kind": "ai-provider",
  "risk_level": "low|medium|high",
  "default_enabled": false,
  "permissions": {
    "network": false,
    "read_metadata": true,
    "read_audio_binary": false,
    "upload_audio_binary": false,
    "write_tags": false
  },
  "network_endpoints": [],
  "data_sent": [],
  "data_not_sent": ["audio_binary", "absolute_path", "cover_binary"],
  "legal_notice_required": false,
  "user_acknowledgement_required": false
}
```

**Load-time admission (enforced by the plugin host):** `api_version` must satisfy the host's accepted semver range; `network=false` for format plugins; any plugin requesting `delete_source_file`, `move_source_file`, or `upload_audio` permissions is **refused at load time** — not merely at runtime.

**Acknowledgement gate:** plugins with `user_acknowledgement_required=true` (e.g. high-risk format migration) must be explicitly acknowledged via `musicforge plugins acknowledge <id>` (or the GUI equivalent) before `format.migrate` is allowed; otherwise the host returns `MF-PLUGIN-ACK-REQUIRED`.

## 4. Format migration plugins (high-risk class)

MusicForge supports local format migration for files **you legally own**. Encrypted or platform-specific containers are handled by optional local format plugins:

- Risk grades: **A** = `.ncm` (built into core); **B** = `.qmc` series / **C** = `.mgg`·`.mflac` (external plugins, per-format compatibility declaration); **D** = platform DRM files (e.g. FairPlay-authorized `.m4a`) — **detected and reported only (`MF-FORMAT-DRM-UNSUPPORTED`), never processed**.
- Format plugins are local-only (`network=false`), preserve source files by default, write output to a user-chosen directory, verify every output (magic/duration/sample-rate/channels/payload), quarantine failures, and record a full Manifest.
- MusicForge does **not** provide, and must never be advertised as providing: online acquisition of encrypted music, bulk platform downloads, bypassing memberships or license checks, sharing of decrypted music, resource indexing/search/aggregation, or cloud processing of user audio.
- Documentation must use the terms "local format migration / backup / demux / conversion" — never "crack / unlock / DRM bypass".

## 5. Runtime limits (enforced by the plugin host)

- Per-request timeout 10–30 s; unresponsive plugins are killed and marked failed (retryable).
- Default concurrency 1–2; remote-API plugins additionally respect user-configured QPS limits.
- **Degradation guarantee:** if every plugin is disabled or dead, all local capabilities (scan / convert / clean / dedupe / organize) remain 100% functional — AI fields are simply marked unavailable.
- Plugin output paths are restricted to the declared work directory and output directory; path escapes (`..`, absolute paths, symlinks) are rejected.
